# PEXserver FileShare 2

PEXserverの共有ストレージ。`PEXServerWebSite/src/renewal.css`の紙色、銅色、青いアクション色とヘッダーに揃えています。

## 起動

Bun 1.4以上とFFmpeg（CPU libx264/AAC）が必要です。

```sh
bun install --frozen-lockfile
bun run build
bun run start --config config.example.json
```

開発用URLは `http://localhost:8100`。`origin`とHostは完全一致が必要です。公開時は `https://share.pexserver.com` 等の確定URLに変更します。秘密鍵は初回にデータディレクトリ内へ0600で生成します。リポジトリにコミットしないでください。

初回だけ、サーバーの`data/bootstrap.token`を読み、トップのログイン →「管理者の初期設定」でユーザー名とキーを入力し、実機のパスキーを登録してください。初期設定キーは24時間で失効し、使用後に削除されます。期限切れの場合はサービスを停止して`bootstrap.token`を削除し、再起動すると未設定の場合だけ再発行します。管理者登録後はキーだけでは管理者を追加できません。予備のパスキーも登録してください。秘密キーをチャット・URLへ貼り付けないでください。

通常の新規登録はIPごとに既定1アカウント、1時間5回まで。パスキー登録後は承認待ちです。管理者だけが`/admin`で承認・拒否・権限変更できます。登録IPはログインで上書きせず、転送ヘッダーからのIP偽装も許可しません。同一NATを共有する利用者には管理者が`accountsPerIp`を調整します。`registration.enabled=false`で新規登録を停止できます。

## 権限

| Level | 名前     | 利用範囲                                                           |
| ----- | -------- | ------------------------------------------------------------------ |
| 0     | 一般     | 公開の共有ファイルの閲覧                                           |
| 1     | VIP      | 既定5GBの個人領域、VIP以上向けの公開ファイル                       |
| 2     | 招待     | VIP機能に加えて、対象キーを使った招待ファイルの閲覧                |
| 3     | スタッフ | 共有領域全般の管理と個人領域。他人の非公開個人領域にはアクセス不可 |
| 4     | 管理者   | 全領域と管理ページ                                                 |

個人領域の所有者はフォルダ・ファイルを公開／非公開／招待に変更し、最低Levelも指定できます。公開ファイルでも親が非公開なら外部へ露出しません。招待キーは256-bit乱数で生成し、サーバーはSHA-256のダイジェストだけを保持します。キー更新で既存の閲覧許可を失効します。招待キーの入力にはログインとLevel 2以上が必要です。ファイルIDとキーは所有者が閲覧者へ別途渡します。閲覧許可は24時間で失効します。管理者と共有領域のスタッフは通常の管理権限でアクセスします。

## ストレージと転送

全体は200,000,000,000 bytes（200GB）、個人領域は5,000,000,000 bytes（5GB）。管理者は個人枠を超えて全体上限内で利用できます。VIP・招待・スタッフの上限は管理者がユーザーごとに変更できます。ごみ箱と未完了の転送予約も容量に含め、並列転送はSQLiteトランザクションで予約します。プレビュー用に全体容量から既定2GBを確保します。これはアプリケーションでの上限で、OSの専用パーティションや物理的な200GB予約ではありません。SQLite・監査ログ等の小さな運用データは別枠です。

アップロードはSHA-256で検証する最大8MiBのHTTPチャンクと、ファイルサイズに応じて256KiB/1MiB/2MiB/8MiBへ動的に選ぶWebSocketブロックと確定オフセットを使用します。256MiB以上では8MiB×最大16ブロックを送信し、1Gbps〜2.5Gbps級の回線でも帯域遅延積を埋めやすくしています。Oracle A1の1Gbps回線でもアプリ側で不要な帯域制限をしない構成（`maxBytesPerSecond: 0`）にできます。ブラウザは約2秒の応答を目標にチャンク量を調整し、失敗時は縮小・指数バックオフを行います。同じタブでは「一時停止」後にファイルを選び直さず「再開」できます（ページ再読み込み後はブラウザの権限制限により再選択が必要ですが、サーバーにある転送済みデータから続行します）。「キャンセル」は転送を破棄し、予約容量も解放します。未完了の転送予約は30分で失効し、巡回処理で予約容量と途中データを解放します。ダウンロードはRange対応。設定した場合のみ転送全体の帯域上限を適用します。バックプレッシャーとIPごとの同時転送制限は常時有効です。回線自体の上限を超える速度や、他アプリの通信負荷の自動検出は保証しません。`maxBytesPerSecond`は`0`でアプリ側の速度制限を解除できます。共有帯域を確保したい場合は実回線速度に応じた上限を設定してください。

### A1一時受信とA8へのバックグラウンド反映

有効化した場合、全サイズのアップロードをA1で受信しながらA8へ並行転送します。各ブロックをA1またはA8でfsyncして受領記録を確定し、A8が現在の権限を検証してメタデータを公開した時点で利用できます。A8への全量コピーはバックグラウンドで継続します。A8の保存確定済み部分はA1で領域解放し、転送途中の読み出しはA8の保存済み部分とA1の未転送部分を連結して配信します。ダウンロードはA8から届く分をA1が順次転送し、容量に余裕がある場合はキャッシュします。認証・容量割当・閲覧許可はA8で一元管理します。

A1のキュー上限は24GB、OS用に8GBの空きを確保します。A8への反映速度がA1への受信速度を下回るとキューが増え、上限到達時は新しい受信を拒否します。A8の確定済み部分を解放することでキューの占有を減らしますが、A1からA8への物理帯域自体は増えません。設定と経路の手順は [A1 edge spool](docs/A1-edge-spool.md) を参照してください。

管理画面から一括ごみ箱移動、復元、明示的な完全削除、期限切れ転送と孤立データの整理を実行できます。フォルダの復元は親から順に行ってください。保存期限を指定していない既存ファイルや通常のごみ箱は勝手に完全削除しません。期限を指定したファイルは期限後に完全削除します。

動画の軽量プレビューはCPUだけで作成します。GPUアクセラレーションなし、1ジョブ、2スレッド、最大480p・先頭120秒・50MB・180秒の実行時間制限。キャッシュも容量制限します。元動画の直接Range再生も可能です。FFmpegは最新の修正版を運用してください。FTPと旧パスワードAPIは削除し、旧JSONユーザーDB・任意の既存フォルダの公開には自動移行しません。

## FerrumProxy / HAProxy PROXY protocol v2

`proxy.enabled=true`でPROXY v2必須、`false`で通常HTTPです。前者ではバイナリPROXY v2ヘッダーがない接続にHTTP 400の「有効な通信プロトコルではありません」ページを返します。`X-Forwarded-For`や`X-Proxy-Protocol-V2`だけでは通過できません。IPv4/IPv6 TCP、分割ヘッダー、keepaliveに対応。LOCAL・UDP・UNIX・多重PROXYヘッダーはクライアントIPとして受理しません。受信元は`trustedPeers`の完全一致で限定してください。TLSはFerrumProxy等で終端し、バックエンドはTailscale等の暗号化されたプライベート経路で接続します。

`deploy/ferrumproxy.example.yml`と`deploy/haproxy.example.cfg`は例です。既存の443リスナーがある場合はホストルーティングへ追加し、既存サービスの設定を置き換えないでください。A8はTailscaleの`100.69.76.52:8100`を使用できます。信頼プロキシは実際の接続元だけに限定し、通常のインターネットへバックエンドポートを公開しないでください。

仕様: [HAProxy PROXY protocol](https://www.haproxy.org/download/2.9/doc/proxy-protocol.txt)、パスキー: [SimpleWebAuthn](https://simplewebauthn.dev/docs/packages/server)。

## セキュリティとAI監視

WebAuthnのOrigin/RP ID/ワンタイムチャレンジ/ユーザー検証を確認し、セッションはHttpOnly・SameSite=Strict（HTTPSではSecure）cookie。セッションの保存はランダムトークンのハッシュだけです。権限変更時に対象ユーザーのセッションを失効。全APIで所有者・親フォルダ・階級・キー許可を再検証します。ファイル名を実パスに使わずUUIDで保存し、HTML/SVG/JS等のアップロードは同一Originで実行させません。CSP・Originチェック・Host検証・監査ログ（30日）・全体/IP別レート制限と接続数制限を適用します。アプリ単体では回線を飽和させるDDoSを防げないため、公開側のFerrumProxy等でも制限してください。

`ai.enabled=true`にすると、10分間のイベント種類と件数だけをOpenAI互換APIへ送り、所見を管理者画面に出します。Gemma 4を使う場合も実際のモデルIDとAPI URLを設定します。AIへファイル内容、招待キー、ユーザー名、IPは渡しません。AIに削除・権限変更などの自動実行機能はありません。API失敗時も認証や転送は継続。認証が必要なAPIには環境変数`FILESHARE_AI_KEY`を設定します。

汎用暗号は別プロジェクト [PEXSecureEnvelope](https://github.com/gamelist1990/PEXSecureEnvelope) の公開AES-256-GCMを使用し、ダウンロードticketを用途別AAD付きで暗号化します。秘密鍵はサービスごとに異なります。実ファイルは0700ディレクトリ・0600ファイルに保存し、ディスク全体の暗号化にはLUKS等を別途使用してください。サーバー本文は配信せず、ブラウザ側JSの秘密保持は前提にしません。独自の謎暗号や透過Unicodeは安全性の根拠にしません。

## A8サービス登録・検証

`deploy/fileshare.service`を`~/.config/systemd/user/`へ配置するユーザーサービス例を用意しています。実行ファイルを`~/.local/opt/pex-fileshare/FileShare`、設定を`~/.config/pex-fileshare/config.json`へ配置します。設定は0600、データは0700にしてください。CPUは合計2コア相当、メモリ1GB、優先度Nice 10に制限します。ログイン前の起動には既存のuser linger設定が必要です。

```sh
bun run build
bun run typecheck
bun test
bun audit
bun run build:exe
# ブラウザテストは独立した一時サーバーとDBを自動で生成して実行
# bunx playwright install chromium
bun run verify:browser
```

ブラウザテストは仮想WebAuthn認証器で初期管理者作成、パスキーログイン、個人領域へのアップロード、公開設定、管理画面とデスクトップ・スマホ表示を検証します。テスト用DBは終了時に削除し、スクリーンショットは`.artifacts/`へ保存してGitには含めません。

CPU変換の実機確認: `FFMPEG=/path/to/ffmpeg bun scripts/verify-preview.ts`。

実際の配置先と未完了の公開設定は [A8 deployment](docs/A8-deployment.md) に記録しています。

## 管理ページ：審査・AI・スタッフ招待

Level 4の管理者は、承認待ちの申請を複数選択して一括で無効化できます。アカウントは削除せず「拒否」に変更し、後から再承認できます。処理は全件をひとつのトランザクションで実行し、承認済みユーザーが混ざると変更しません。

審査・監査ログは日本時間の日付ごとの「本棚」から選択します。年月と審査のみ／すべての記録を切り替え、過去のログを100件ずつ参照できます。ユーザーの審査・権限・容量の変更は変更前後も記録します。

AI監視の有効／無効、モデル名、実行間隔（60〜3600秒）を画面から変更できます。設定はSQLiteに保存され、再起動後も有効です。接続先とAPIキーは引き続きサーバー設定・環境変数で指定します。AIへ送るのは操作名と件数のみで、IPやファイル本文は送りません。AIは所見を作るだけで、権限変更や削除は実行しません。

スタッフ招待URLは既定で7日間・1人までです。有効期間は1〜720時間、利用人数は1〜100人から選択でき、失効も可能です。URLの秘密部分はフラグメントに含め、サーバーはハッシュだけを保持します。発行直後だけURLを表示するため、控えを失った場合は失効・再発行してください。招待先で新しいパスキーを登録するとLevel 3・承認済み・既定5GBで作成されます。招待は通常登録の停止・IP別アカウント上限とは別に管理しますが、認証APIのレート制限は適用します。利用回数は登録成功時に原子的に消費し、期限・失効・利用回数と招待発行者の管理権限を再確認します。発行者が管理者でなくなった場合も、その招待は無効になります。


## ファイル記録・ランキング・保存期限

投稿者はアップロード前、または各ファイルの設定で保存期間を選択します。既定では1分〜30日で、アップロード完了時刻を起点に計算します。期限になった時点で一覧・ダウンロード・プレビュー・招待からの閲覧を停止し、1分ごとの整理で本体とプレビューを完全削除して容量を解放します。期限後は復元できません。更新前の既存ファイルには期限を付けず、変更するまで維持します。

管理ページで、保存期間の最大、1ファイルの容量上限（既定5GB）、ダウンロード記録の有効／無効、件数と投稿者名の公開、公開ランキングを変更できます。期間上限の変更は新規投稿と期間変更に適用します。容量上限は転送開始・再開・確定時にチェックします。投稿者・ダウンロード数・保存期間はファイルごとの管理欄でも調整でき、変更を監査ログへ記録します。投稿者の初期記録は実際に転送したユーザーです。既存ファイルは監査ログから分かる範囲で補完します。

明示的なダウンロードで配信したリンクごとに一度だけ集計し、同じリンクのRange・再開は重複させません。HEAD・プレビュー・無効なRangeは集計しません。公開ランキングは閲覧許可のある公開ファイルだけを対象とし、親が非公開のファイルや期限切れのファイルを表示しません。管理者用ランキングは非公開ファイルも対象です。

### 招待限定登録と一般ユーザーの投稿

標準では新規登録は有効な招待URLを持つ人だけに限定されます。登録済みアカウントのパスキーログインには影響しません。管理ページの「VIP・スタッフ招待URL」で権限を選択してください。VIPはLevel 1と既定5GB、スタッフはLevel 3です。期限・利用人数・失効と発行者の管理者権限を、登録の開始時と確定時の両方で検証します。既存スタッフ招待は引き続きLevel 3です。

管理ページの「登録・一般ユーザーの投稿」では一般登録、自動承認、承認済み一般ユーザーの共有領域への投稿を独立して設定できます。自動承認もパスキー認証とIP別の登録制限を維持します。一般ユーザーの投稿許可は既存ファイルの変更・削除・公開設定やフォルダ作成を許可しません。設定はデータベースに保存し、反映後の転送再開にも適用されます。configのregistration.enabled=falseは一般登録を停止する上位の設定です（有効な招待と初期管理者設定は利用可能）。

### 投稿者ページとプレビュー

`/rankings` はファイル・投稿者別のランキング、`/users/<user-id>` は閲覧権限に応じた投稿一覧です。DL数はk/m表記です。VIP（Level 1）・スタッフ・管理者は `/profile` で説明、HTTPSのSNSリンク、256KB以内のPNG/JPEG/WebPアイコンを設定できます。管理者の投稿者表示スイッチをOFFにすると投稿者APIも非公開になります。

各ファイルの `/files/<file-id>/preview` で画像、PDF、音声・動画、Markdown、テキスト・コードを表示し、プレビューURL・直リンク・埋め込みiframeをコピーできます。非公開の親フォルダ、招待鍵、権限、期限切れは各リクエストで確認します。リンク自体はアクセス許可を付与しません。HTML/SVG/コードは実行せずテキストとして表示、Markdownの生HTMLと外部画像は無効です。テキスト表示は先頭512KBまで、非対応バイナリはダウンロードして利用してください。PDF表示はブラウザのPDF機能に依存します。

### HTTP/3広告

FerrumProxyの `https.http3` を有効化し、UDP443経由でサービスへの到達を検証してから、FileShareのconfigで `http3Port: 443` を指定してください。既定0は広告無効です。Alt-Svcは5分間有効。HTTPS/TCPとwget・Range・通常のダウンロードURLを維持します。ブラウザのWebSocketパイプラインは引き続きTCPを利用します。

### VIPの共有権限・別端末のパスキー登録（2.9）

VIPは既定で共有領域への投稿・編集ができません。管理画面の「登録・共有への投稿・パスキー」で、VIPの共有への投稿と編集（削除・フォルダ作成を含む）を独立して設定できます。一般ユーザー向けの投稿許可はLevel 0だけに適用します。VIP自身の個人領域は従来通り利用できます。共有権限を取り消すと進行中の転送も再確認します。

「パスキー追加」から、同じ端末への追加または別端末用の登録URLを発行できます。URLは10分間・1回限りで、再発行・無効化に対応し、トークンはハッシュのみ保存します。登録先の端末でURLを開いて本人のパスキーを作成し、そのパスキーでログインしてください。URLはアカウントへのパスキー追加を許可する秘密情報です。本人の端末だけに渡してください。登録上限は既定3件、管理画面で1〜100件に設定できます。認証開始時と登録確定時の両方で上限を検証し、同時登録でも超過を防止します。上限を下げても既存パスキーを削除しません。同期型パスキーは複数端末で共有されるため、上限は物理端末数ではなく登録パスキー数です。

動画はブラウザ標準プレーヤー（インライン再生・メタデータ先読み・Range対応）を使います。作成済み軽量版は自動再利用し、元の画質へ切替可能です。軽量版の作成は明示操作時のみ、CPU2スレッド・最大640x360・24fps・H.264/yuv420p・映像400kbps（最大480kbps）/音声64kbpsで行い、MP4のmoovを先頭へ配置します。非対応のコンテナ/コーデックは軽量版を利用してください。

### 投稿者検索・通知（2.10）

ナビゲーションのUser (`/users`) で投稿者を名前から検索できます。24人ずつ追加表示し、投稿者ページからその人のファイルへ進めます。閲覧できるファイルのある承認済み投稿者だけを表示し、非公開の親フォルダ、招待制限、期限切れ、投稿者表示設定を検索時にも確認します。IPやアカウント管理情報・非公開ファイル数は返しません。

コピー・保存・アップロードなどの完了通知は画面隅のトーストへ統一。成功4秒・エラー8秒で閉じ、ホバー・キーボードフォーカス中は一時停止します。同じ通知はまとめて、最大3件を表示。表示・終了アニメーションと残り時間バー、手動閉じるボタンに対応し、動きを減らすOS設定ではアニメーションを停止します。入力エラーの説明や一度だけ発行される招待キーは、確認できる専用表示に保持します。

### プロフィールのカスタマイズ（2.11）

VIP・スタッフ・管理者は `/profile` で表示名・カバー画像・アイコン・説明・所在地・SNSリンクを編集できます。ライブプレビューを見ながらカバーの表示位置を調整でき、PNG/JPEG/WebPはブラウザ内で縮小・WebP化してから送信します（入力12MBまで、保存時アイコン256KB・カバー768KBまで）。従来のユーザー名は変わりません。公開投稿者ページはカバーとアイコン、ファイルのタイムライン、メディア切替、プロフィールURLの共有に対応。表示件数は現在の閲覧権限で取得したファイルだけを数え、続きがあれば追加表示できます。表示名でも投稿者を検索できます。一般・招待ユーザーはカスタマイズできず、管理者が投稿者表示を無効にすると公開プロフィールと画像も非公開になります。既存プロフィールは起動時に追加列を移行して保持します。

### 共有URLのプレビュー（2.13）

`/?item=<ID>` と `/files/<ID>/preview` は、JavaScriptなしでも取得できるHTMLへOpen Graph・Twitter Card・canonical・ページタイトルを出力します。匿名閲覧可能なファイルでは名前・容量・投稿者表示設定に沿った投稿者名を反映し、8MB以内の対応画像は公開画像URL、MP4/WebMは動画URLも指定します。非公開・階級制限・招待限定・期限切れ・非公開の親フォルダを持つファイルは、ログイン済みの所有者や管理者が開いてもOG情報へ名前やコンテンツURLを含めません。共有先のカード表示には、そのサービス側の対応形式やキャッシュも適用されます。

## 2.14: 管理・検索とA1バックグラウンド転送

- VIP・スタッフ・管理者は保存期間に「無期限」を選べます。個人領域の初期値は無期限で、保存期間は領域別Cookieに保持します。管理者の個人領域も割り当て容量を適用します。共有領域は共有全体の容量で管理します。
- Ranking・User・Search・プロフィールでも同じ権限のナビゲーションを表示。管理画面はユーザー検索、権限／状態フィルター、50人ごとのページ分割、カテゴリ別操作と使用状況の概要を備えます。
- マウス環境ではファイル／フォルダをドラッグして同じ領域のフォルダやパンくずへ移動できます。外部から複数ファイルをドロップすると、中央の確認画面で期限・タグを設定して送信できます。移動はサーバーで権限と循環を確認し、複数選択も一括で確定します。
- ファイルには最大10個のタグを設定可能。Search (`/search`) は匿名でも閲覧できる公開ファイルだけを対象に名前・タグで検索します。非公開の親、階級、招待、期限は検索にも適用されます。
- アイコンは丸枠で位置・拡大率を調整して切り抜けます。選択した画像名と保存済み画像の状態を表示し、カバー位置調整も維持します。ランキングは順位・アイコン・表示名・件数を整理しました。
- 管理者はストレージのマッピングで、A8にマウント済みのディレクトリ／外部ドライブへ専用保存先と追加容量を登録できます。通常ファイルをUUID名で保存し、既存ドライブの任意ファイルを公開する機能ではありません。停止は新規書き込みを止め、保存済みデータと参照先を保持します。初期容量は基本ドライブ分で、追加した保存先の割当を合算します。
- A1は受信を続けながらA8へ並行転送。全量のfsyncと受領記録が揃えばA8への全量コピー完了を待たずに利用可能になります。ダウンロードもA1の受信データ／キャッシュから配信し、コールド読み込みはA8からストリーミングします。配信前に毎回A8で現在の権限を検証します。容量制限・耐障害性・導入手順は [A1 edge spool](docs/A1-edge-spool.md) を参照してください。
- AI監視はOpenAI互換EndpointとAPIキーを管理画面で設定し、モデル一覧を自動取得して選択できます。保存キーはAES-256-GCMで暗号化し、管理API・監査ログへ平文で返しません。AIが受け取るのは数値集計のみで、自動削除・権限変更はしません。接続方式は公式の [モデル一覧](https://developers.openai.com/api/reference/resources/models/methods/list) と [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) を参照。

生成されたHTML/JS、実験動画、ローカル共有サンプル、Pythonキャッシュ、秘密情報・実データはGitの追跡対象から外しています。既存のローカル実験ファイルは保持しています。クローン後は依存を導入し `bun run build` を実行してください。

### 2.15: 確定済みブロックの領域解放

A8の耐久受領後にA1の対応領域を順次解放します。受領記録の保存を先行し、解放済みの部分をA1のゼロ領域から読み出さないようにします。転送途中でもA8の確定済み部分とA1の残りを連結し、Range・テキストプレビューにも対応します。ダウンロードは256KiB単位で到着した分を流し、低速クライアントのバックプレッシャーをA8まで伝えます。未受領部分の先行削除や、ファイル全量のメモリ保持は行いません。

### 2.17: ドライブ検出と切断・再接続

管理画面の「ストレージ」でA8のマウント済み・書込可能なドライブを検出し、選択と容量の自動設定／プリセットで追加できます。詳細設定から既存ディレクトリも指定できます。同一ファイルシステムの既存割当は差し引き、重複割当を防ぎます。ドライブを追加しても論理フォルダ・ファイルID・URL・権限は変わらず、ストレージ全体の割当容量が増えます。ユーザーの個人容量上限は別途維持します。OSでのマウント操作そのものは行いません。

専用保存先には識別マーカーを置き、取り外し・別ドライブへの入れ替え・元データの欠落／サイズ不一致時は「破損・接続不可」と表示し、ダウンロード、A1キャッシュ配信、プレビューは404で拒否します。フォルダやメタデータは残し、正しいドライブが戻れば同じURLで再利用できます。ファイル一覧と管理画面は15秒ごとに状態を更新します。

接続不可の状態で削除したファイルは復元対象に戻しません。削除予約をA8のSQLiteへ耐久保存し、再接続時の巡回（通常最大1分）または管理画面の再検出で実データを削除します。期限切れ・完全削除もこの予約を使い、メタデータを完全削除した後やサーバー再起動後も予約を保持します。既存ドライブを停止する操作は新規保存だけを止め、既存データは保持します。ドライブを消去する機能ではありません。
